# Even frontend

Base UI-backed controls and React product components for the v1 trace explorer, inspector, and secondary playground. Shared defaults use decision tokens and support light/dark themes. Shared components have no model calls or API integration; the connected page owns API access. Each component has a colocated implementation, Storybook stories, and behavior tests.

## Trace viewer v0 stories

Start at **Trace viewer / TraceViewer / Composed**. The independent **TraceBreadcrumbs**, **TracePath**, **TraceObject**, and **TraceRawPanel** stories isolate the viewer pieces. The composed viewer also has Nested Agent, Long Execution, Partial Trace, Empty, Loading and Error stories. Data in these stories is synthetic, reader-shaped fixture data; no agent executes and no backend request is made. The application and its trace table are unchanged.

`TraceViewer` exposes `Breadcrumbs`, `Path`, and `Raw` compound parts. The root coordinates the current activation, span selection, expansion and independent reading positions through product context. It accepts a supplied `{traceId, spans}` record, optional `initialActivationId` / `defaultSelectedSpanId`, loading/error/retry state and presentation props. It resets navigation when the trace ID changes. Parts can be placed declaratively; the default composition supplies all three.

`TraceBreadcrumbs` renders a native navigation/ordered list with Base UI-backed ancestor buttons and `aria-current="location"` on the current activation. The optional `onSelectCurrent(id)` makes the current crumb inspectable; the composed viewer uses it to show the activation’s original JSON without navigating. Supply `{id,label}` items and `onNavigate(id)`. `TracePath` removes only the current activation’s row and promotes its actual operations; the activation remains in the breadcrumb and the raw data is intact. The default selection is the first visible operation. Child activations remain navigation rows. `TracePath` composes the existing `SpanWaterfall` tree: arrows move focus, Right/Left expand/collapse, and Enter/Space select. One non-interactive SVG path connects visible neutral markers within each step, using rounded right-angle elbows as indentation changes; deeper levels are approached horizontally from the left of their marker. The final descendant of a step does not connect back to the next sibling step: that step starts a new subpath, including when the preceding step is collapsed. Recorded parent-to-child links into nested steps remain intact, and traces without recorded steps keep their continuous route. It measures rendered rows, follows resizing and expansion, and stays above row highlights but below the marker stations and text. Dotted vertical guides mark ancestor columns across each expanded branch's visible descendants. They start and stop at branch boundaries. They stay visible without hover or selection and have no horizontal connectors. Both paths use `hierarchy.guide` (neutral 6), with explicit 3:1 contrast checks against supported surfaces in both themes and gamuts. Both paths update immediately without motion or per-frame React state. A single neutral circular marker anchors each row on the curved path; categories are written in text rather than encoded by different glyphs. Branch stations are tree-owned disclosure controls; leaf stations select the operation. Stations have an opaque page backing so the line does not run through them. Selected stations use `selection.indicator` for both their border and solid fill; other stations remain outlined. Their borders meet 3:1 against the backing. Resting titles use `text.secondary`; row hover or visible keyboard focus uses `text.primary`; selected titles use `selection.foreground`, including during hover/focus. Markers use the same resting/hover/focus text roles as titles, while selected markers retain `selection.indicator`. Category labels stay secondary through unselected hover/focus and use `selection.foreground` when selected. Duration and token counts are absent from explorer rows; the data panel header shows metrics for the selected span. No opacity reduction is applied. Rows use `size.control.default` with `space.gap.related` vertically for breathing room. The rail indicates hierarchy and ordering, not duration or a claim of sequential execution. The Long Titles story exercises one-line overflow and a multi-level return. Step grouping and metadata use the supplied evidence; error status is explicit, and status UNSET is not relabeled successful. Selection, expansion and presentation can be controlled. `SpanWaterfall.Tree` additionally supports `className`, `getLabel(span)`, `getDescription(span)`, `renderLabel(span, {hasChildren, expanded})` and `renderToggle(span, {expanded})` so path presentation does not duplicate its keyboard engine. Its optional `onActivateSpan(id)` runs on every pointer or Enter/Space activation, including an already selected row; selection-change callbacks keep their change-only contract. `TracePath` uses activation to allow repeatedly opening a subagent after returning to its selected row.

`TraceObject` is the presentation-only single-row body: category and title. Categories use a consistent `size.label.category` column (64px-equivalent), `text.secondary` and plain text without badges. Titles at the same tree depth align. Dense path rows use `size.object-row.minimum` (256px-equivalent); narrow paths scroll horizontally rather than collapsing the title to zero width. The composed viewer retains both path scroll axes across scope navigation. Step titles span the category/title columns because “Step 0” already identifies the type; no duplicate Step label appears. Long titles ellipsize while the full name and category remain in the accessible tree label and raw JSON. The surrounding tree owns interaction. Its independent stories include Step, Model, Tool, Long Name and Category Catalogue. **Category Pill Mockup** in both TraceObject and TraceViewer previews the supported `categoryAppearance="label"` variant. `TraceObject` and `TracePath` default to `"plain"`; the mockup opts in through `<TraceViewer.Path categoryAppearance="label" />`. Styling lives in the shared `even-components` layer, with no Storybook CSS overrides. Resting pills use translucent `label.background` (gray-alpha 2); selected pills use `label.selected-background` (gray-alpha 3), making the white overlay a little brighter in dark mode while blue selection still shows through. Resting text uses `label.foreground`; selected text uses `selection.foreground`. Only the fill is translucent; text stays opaque. Step 0 itself serves as the step label. Capsule labels use `size.radius.pill`, with `space.inset.tight` vertical padding and `space.inset.default` horizontal padding (4px / 16px equivalents). The aligned column reserves the existing category text width plus its two inline insets; this is derived layout geometry rather than a new size option. Native styling overrides and component behavior are preserved.

Category labels come from recorded operation types through `describeSpan`: Model, Tool, Skill, Agent, Delegation, Memory, Approval, and Span for unfamiliar operations. Read/write/search tool operations all use Tool; names remain intact, and no tool-name heuristic claims side effects. `TraceObject` accepts an optional `category` override for product context; `TracePath` supplies Subagent for descendant activation rows, while standalone activation objects default to Agent. The trailing subagent arrow remains a decorative navigation cue. The category mapping can grow without changing tree behavior or raw records.

The supported Eve 1.0.0-rc.6 instrumentation emits `agent.step` spans under activations, with `agent.step.index` and `agent.step.attempt`. Steps are an expected Eve shape, not a requirement of arbitrary OpenTelemetry traces: No Steps, Activation Only and partial-data stories preserve the available operations without inventing steps. Explicit span usage is preferred when supplied. Otherwise step token counts sum recorded input/output usage within the step, stop at recorded model wrappers to avoid counting nested SDK usage twice, and exclude child activations. Missing model counters make the known sum a lower bound; cached input details are not added a second time. These are totals of supplied records, not estimates or guarantees of complete trace coverage.

The small `src/traces/traceModel.js` presentation adapter derives labels and activation boundaries without changing span records. Selecting an ordinary span displays its full supplied record. Selecting a recorded descendant activation opens that agent's own scoped tree, stopping at the next activation boundary. Parent breadcrumbs restore selection, expansion and path/JSON reading positions, and put keyboard focus back on the selected operation. Missing-parent and cyclic spans remain inspectable; unowned spans remain in the initial view. No conversation IDs, matching names or tool names are used to invent ancestry. Remote dispatches remain inspectable JSON; separate-trace linking awaits backend link support.

`TracePath` has no visible title/count header; its section and tree retain accessible names. Descendant activation rows have a trailing right arrow to distinguish opening another execution from expanding an ordinary branch. Their accessible descriptions explain Enter-to-open; ordinary branch expansion remains in place.

Subagent navigation keeps the viewer frame and breadcrumb stationary. The current breadcrumb has stronger text emphasis, and the composed viewer enables `TraceBreadcrumbs showBack` to offer a visible “Back to [parent]” action. Returning restores expansion and reading positions, selects the subagent row entered from, and focuses that row. A polite status announces the current execution. The optional `showBack` prop defaults off in standalone breadcrumbs; ancestor/current-inspection callbacks retain their existing contracts.

Pointer navigation uses `motion.duration.move-large` / `motion.easing.move-large` (350ms). The old scope shifts slightly left while exiting, then the child enters from the right; returning reverses direction. Both panels move at their original scale over `space.gap.group`. The outgoing fade occupies the first 35% of the timeline, and incoming text appears in the remaining 65%, preventing overlapping JSON/tree text. The live scope, data and focus update immediately. Temporary inert, accessibility-hidden snapshots preserve outgoing pixels and scroll positions, contain no duplicate IDs or keyboard targets, and are removed on completion. A new navigation replaces pending decoration; keyboard input, resizing, preference changes and unmount cancel it. Keyboard navigation is immediate. Reduced motion uses the `reduced` opacity-only timing (100ms), with no translation. WAAPI reads resolved motion decisions and caller overrides through the shared timing helper; no animation dependency was added.

`TraceRawPanel` accepts `span`, optional `tokenUsage: {count,partial}`, loading/error/retry state and presentation props. The code header shows the selected span’s duration and optional token count at the top left, with the compact `JSON` label and clipboard button at the top right. These stay above the independently scrolling JSON. There is no separate title, caption or copy footer. The host supplies aggregated step usage; standalone panels read only explicit usage from their supplied span. `≥` marks a lower bound, missing usage is omitted, recorded zero stays zero, and unavailable duration is labeled unknown. The RawPanel Step Usage, Partial Usage, Zero Usage and Unknown Metrics stories cover these states. It reuses `PayloadViewer highlightJson`: JSON syntax coloring is optional and text remains escaped React content. Embedded JSON strings remain strings; unknown fields are preserved, bigint timestamps serialize as decimal strings, and copying uses the complete serialized record. This is the parsed span supplied to the UI, not the original OTLP file. There is no model/tool-specific detail UI in v0. The code region supports keyboard scrolling. The reused `CopyButton iconOnly` changes its clipboard glyph after success and announces the result; failure text remains visible with retry available. `PayloadViewer` exposes a `toolbar` slot and `showCopyButton` flag for this composition; its default text copy action is unchanged. At narrow widths, the bounded path stacks above the raw panel.

Existing surface, selection, spacing, size, font, focus and motion decisions cover the layout and scope navigation. The `hierarchy.guide` decision covers meaningful connectors and nesting guides. The added `syntax.key/string/number/literal/punctuation` color decisions provide text roles for JSON and are audited on page/secondary surfaces in both themes and gamuts. The path reuses `size.radius.control` for elbow corners. UI typography remains provisional as documented below; no new type scale, layout-size option or motion token was introduced.

## Connected browser app

Even serves the production app and API from one local origin. Build with `npm run build:ui`, then launch `npm start -- --project /absolute/path/to/eve-project`. The CLI opens the browser automatically; `--no-open` is available for automation. The launch fragment is consumed and removed before rendering, exchanged for a temporary HttpOnly session cookie, and discarded. Refreshes and additional tabs use that cookie automatically. There is no manual token-entry or disconnect screen.

`pages/ConnectedApp` loads inventory and selects the first agent. It supplies an API client to HomePage through `dataSource`, with `initialAgentId` and `allowAllAgents={false}`. `useTraceData` owns debounced requests, newest-first search, retained per-source completion metadata, pagination, cursor invalidation, incomplete coverage, reload observations and cancellation. `useTraceDetail` fetches full spans on demand and keeps detail failures inside the inspector.

Same-query refresh retains loaded rows during loading or failure, preserving the mounted table and focus. Each tab’s trace controller owns column widths and the selected summary so refreshing the first page does not discard an older inspected execution. A changed query or source clears selection and pagination while preserving column widths.

Autocomplete combines inventory names with observed tool/agent summary metadata retained per agent and data-source instance, independently of the current result set; suggestions are not exhaustive backend facets. Neither hook evaluates agent code. The browser remains passive; session creation and live conversation integration follow separately.

The client uses relative same-origin API URLs. It does not connect the Vite development server to a different backend origin. Use the backend’s browser link for real data and the Vite staging page or Storybook for fixture development. The compiled app is included in the npm package; React, Vite and Storybook remain frontend development dependencies.

`EVEN_TEST_NODE_MODULES=/absolute/path/to/project/node_modules npm run test:app` at the repository root runs a real browser against an isolated Eve project. It verifies automatic connection, refresh, additional tabs, new-launch handoff, actual indexed traces, newest-first ordering, refresh preserving inspector/widths/focus, retained autocomplete, multiple result pages, span inspection, cookie-authenticated writes and passive operation, with accessibility checks in both themes.

## Workbench tabs

The sidebar restores an independent tab set for each agent. Long agent lists scroll within the sidebar; narrow layouts retain the horizontal agent scroller. The connected app selects its first inventory agent. **Traces** is pinned and cannot close. **New tab** offers **New trace explorer** and **New chat playground**. New tabs activate and receive focus. Trace explorers keep their query, recent completions, widths, loaded pages, inspector selection/view, expanded spans and table scroll independently. Agent changes restore the previous active tab. All state is in memory and resets on a browser reload.

`HomePage` owns tab metadata and lifecycle through `workspaceState.js`. Each private `TraceExplorer` controller remains mounted for its stable `(agentId, tabId)` while only the active panel’s content mounts. This keeps controller state and read results separate from visible DOM. In-flight reads may finish into their own retained controller; closing the tab aborts pending reads. There is no background polling or automatic refetch on tab activation. Refresh remains explicit. Inactive panel shells stay mounted for stable accessible relationships. Inspectors restored with a tab use `autoFocus={false}` and retain a reference to that tab’s Operation action for close-focus restoration.

Closing an active tab chooses the right neighbor, otherwise the left; closing an inactive tab keeps the active view and focuses its trigger. Delete closes a focused unpinned tab unless the caller cancels with `preventDefault()` or `preventBaseUIHandler()`. Base UI owns arrow/Home/End navigation, automatic activation and tab/panel relationships.

Tab labels have a leading decorative type icon: `kind="traces"` uses Lucide `list-tree`; `kind="playground"` uses `message-square`. The default kind is `traces`; an unsupported kind has no icon. `HomePage` supplies the tab record’s kind. Icons use `size.icon.default` and the tab’s current text color; `space.gap.related` separates icon and label. The label alone keeps its overflow fade, so the type icon stays clear at compressed widths. Icons are hidden from assistive technology and never add a tab stop or change the tab/close accessible names. Vendor aliases live in `components/icons.js`; the tab-kind mapping lives in `components/WorkbenchTabs/tabIcons.js`. This keeps the trial vendor choice out of page callers and makes a later icon-set change local. [Lucide React usage](https://lucide.dev/guide/react).

Tabs share equal width, capped by `size.navigation-item.maximum` (192px-equivalent) and shrinking toward `size.navigation-item.minimum` (128px-equivalent) as their count grows. Long labels fade beneath the close control while keeping their full accessible name; a CSS mask clears the text before the X glyph rather than appending an ellipsis. At the minimum, the strip scrolls instead of squeezing labels and close controls further. The scrollbar is hidden; overflow scrolling and automatic reveal of the focused/active tab remain available. Closing tabs reclaims the removed width, pulling overflowed tabs from the left into the freed end space. Decorative edge fades stay within the remaining track bounds and cannot extend its scroll range. The strip suppresses vertical scrolling and vertical overscroll. Tab and close-button pointer hover effects pause throughout scrolling and restore under the pointer 120ms after the last scroll movement. Trailing wheel input at a boundary does not extend that cooldown. Keyboard focus remains visible. Horizontal gestures stay contained at either end to prevent browser swipe navigation, with native horizontal edge feedback suppressed. The group stays right-aligned when it has spare space. The pointer cursor stays continuous across the thin seams and curved corner gaps within the tab group; unused strip space keeps the default cursor. The plus control remains outside the scroller, overlaps its right edge, and looks like an inactive tab: no folder outline or curved shoulders, a neutral foreground at rest, and the same inset highlight on hover or while its menu is open. The strip baseline continues beneath it. The plus reserves a transparent leading `size.radius.panel` region where the active shoulder can complete; canvas paint begins after that curve and hides the overflowing tabs beneath the icon. Its hover highlight remains inside the click target and has the same tight side/bottom clearance and concentric inner corner as an adjacent inactive tab. Leading/trailing edge fades sit below the active layer and appear only while more tabs remain offscreen in that direction. The active tab uses native horizontal sticky positioning at both boundaries, so inactive tabs pass behind its fixed-width body. The same selected tab and its close control remain interactive; no duplicate tab is rendered. Full-height backdrops continue to the tab wall and opaque canvas cutouts hide passing content in both curved shoulder gaps, with fades just outside those curves. These decorative backdrops are children of the sticky tab, so the browser moves them together during scrolling and native edge feedback. They paint behind its outline using gradient border-image outsets, which leave the scroll range unchanged. Keyboard focus on another tab’s close control reveals it beyond the active frame and its fade without changing selection. Scroll and ResizeObserver measurements coordinate these visual edges; they do not own selection or keyboard navigation.

One decorative Base UI Tabs.Indicator forms the selected tab’s rounded outline and curved lower shoulders joining the panel’s secondary surface, so the title and contents read as one view. Its outline and curved edges use `border.default`, matching the strip baseline. Keyboard focus keeps the shared focus color with an inset outline to avoid clipping at the connected edge.

Short decorative dividers separate consecutive inactive tabs using `border.default` and the shared stroke width. Neither side of the active tab has a divider. Hovering an inactive tab hides both surrounding dividers, including while the pointer is over its close control; they return when hover leaves. Dividers do not affect tab widths or accessible roles. Inactive tabs use an inset hover shape with concentric corners: its radius is the active shoulder radius minus the stroke and clearance, clamped at zero (`size.radius.panel − size.border.control − space.inset.tight`, currently 8 − 1 − 4 = 3px-equivalent). Tab slots touch; the hover inset supplies equal 4px-equivalent visible clearance beside an adjacent active tab and above the painted baseline. Vertical insets include the baseline stroke, while horizontal insets account for the reserved tab stroke, so the lower hover corner and active shoulder share a center. The inactive hover shape is shorter and centered around its label, balancing the space above and below. Label positions stay aligned with the active tab; the full hit area stays unchanged. The full tab remains the hit target, and the hover shape and label foreground persist while the pointer moves onto the close control. Active tabs keep their normal surface; only their close control reacts. The close button uses a compact square target (32px-equivalent by default) with a smaller, inset hover highlight (24px-equivalent by default). Its radius is derived from the enclosing surface's curve minus the actual clearance, clamped at zero; the tight inset keeps the highlight inside either tab surface. The right clearance matches the vertical clearance of the enclosing surface, including when the active tab is pinned against either scroll boundary; the inactive tab’s inset hover needs a tighter trailing margin than the active tab outline. ## Search prototype

`ThemeToggle` is a Base UI RadioGroup with two fixed icon choices: Lucide Sun Medium for light and Moon for dark. It accepts controlled `value`/`onValueChange` or uncontrolled `defaultValue`, plus primitive disabled/read-only/cancellation and styling APIs. The host applies the selected theme to the HTML root; the generic control does not write global theme state. `HomePage.theme` / `onThemeChange` place it in the bottom-left sidebar footer. The connected and staging hosts retain their existing theme state; the previous header action is removed. At narrow widths the sidebar footer becomes a second row beneath agent navigation. **Primitives / ThemeToggle** contains the isolated examples; **Pages / HomePage** connects the selector to Storybook’s theme global. Search, tabs and inspector state remain intact when changing theme.

The staging home page now uses **Workbench / TraceSearch**, a controlled composition of Base UI Autocomplete. It shows “Search traces...” as its placeholder with no visible title or persistent helper text; the `label` prop supplies its persistent accessible name. A decorative Lucide search icon sits inside the leading edge of the field, sized with `size.icon.default` and separated from text with spacing decisions. It adds no focus stop, accessible-name text or pointer obstruction. Focus strengthens the search border with neutral `border.focus` (step 9) and `size.focus.inset` (1px), combined with `size.border.control` (1px) to produce a 2px edge without changing border width or layout. Invalid focus keeps `border.invalid`; forced-colors mode uses an inset system-color outline because shadows may be suppressed. Other controls retain their outer focus rings. Clicking the input opens examples; `tool:` and `agent:` suggest values from supplied traces. Arrow keys and Enter select a suggestion, Escape dismisses it, and the clear action resets the query. Filtering previews every edit. Enter or choosing a suggestion remembers up to three recent queries for that page instance. History is not persisted.

Browser checks cover both themes, 390/768/1280px widths, pointer/keyboard selection, repeated Tab dismissal, validation and matched-span navigation. ## Trace column sizing

`TraceToolbar.searchControl` replaces its default search input and clear button with a supplied control; existing callers keep their original behavior. `TraceTable.renderOperationDetail(trace)` adds noninteractive content to the full-cell operation action. That visible content participates in the action’s accessible name; callers should query the operation by a name containing its title when details are supplied. Data interpretation and selection of the matching span belong to the page.

`TraceTable` uses the self-hosted Geist Mono variable font through `decision.font.data`, with Agent and Operation columns using the regular system sans-serif through `decision.font.ui`. Those exceptions include their headers and the Operation cell button. Font assets ship with the frontend via `@fontsource-variable/geist-mono`; no runtime font CDN is needed. Other UI controls keep their existing appearance through the same UI-font decision.

Pass `aria-label` to give the results scroll region a distinct accessible name when composing multiple tables; the default is “Recorded trace results.”

`TraceTable` keeps column widths locally by default. Pass `defaultColumnWidths` for initial overrides, or `columnWidths` with `onColumnWidthsChange` for controlled widths. Keys are `startedAt`, `durationMs`, `agent`, `operation`, and `calls`; override values are finite CSS-pixel numbers, clamped to each column’s limits. Passing an empty controlled map restores defaults. Outcome has no handle and fills the remaining space with a minimum width.

Uncontrolled widths have one private table-local store, consumed through `useSyncExternalStore`; resize commands publish immutable snapshots and complete-map callbacks without a commit-time ref mirror. Batched changes to different columns preserve each other, and repeated no-ops do not emit callbacks. Controlled maps remain authoritative until the parent updates them.

`selectedOperationRef` accepts a React object or callback ref for the selected row's Operation button. React clears it when that button loses selection or unmounts and registers the replacement after row/tab restoration. The host can use it for inspector return focus without querying table markup. **Selected Operation Target** demonstrates this contract.

Preferred/minimum widths live in the component’s `columns.js`; defaults use rem and track root text sizing. User adjustments are runtime state, rather than design tokens. Existing control-size, border, inset, and focus decisions style the handles. A native `colgroup` and fixed table layout size every row together; excess width stays in the scroll container. Cell text stays on one line and uses a fixed right-edge ellipsis when it overflows, including inside the full-cell Operation button. An internal `CellOverflow` masks complete graphemes at measured text boundaries and reserves room for a decorative marker anchored to the right inset; full text remains in the DOM and accessible names.

The resize dividers are hidden at rest and appear in Neutral 3 (`border.default`) when the header row is hovered. Hovering a handle or dragging emphasizes that handle with `border.interaction`; keyboard focus reveals its line and focus ring even without hover. Hit targets and keyboard navigation remain available while the decorative lines are hidden.

Drag a header’s right divider, or focus it and use Left/Right (8px), Shift+Left/Right (32px), Home (minimum), and End (maximum). Escape cancels an active drag. Resizing does not sort or select traces. **Controlled Column Widths** and **Narrow With Long Content** stories demonstrate state ownership, resets, and ellipsis.

**Character Ellipsis** demonstrates the standard overflow treatment with long labels and emoji. Drag Operation’s divider or use its keyboard controls; widen it to restore the full text. This is component presentation with no motion or new design tokens. The full semantic content stays mounted; ResizeObserver and font loading update the mask. Native ellipsis is a fallback where measurement is unavailable or for right-to-left content.

**Inline Ellipsis Experiment** previews native inline ellipsis on the existing resizable table. The marker follows the visible text; the remaining gap is after the marker. Its toggle compares with current fixed-marker behavior. The scoped Storybook stylesheet overrides presentation only; component defaults and typography are unchanged.

## Data boundary

The current backend returns full traces with spans and nanosecond strings. `TraceTable` and `TraceSummary` intentionally consume a **summary view model**: `traceId`, optional `label`, `startedAt`, `durationMs`, `agentNames`, `spanCount`, `modelCalls`, `toolCalls`, `errorSpanCount`, and explicit `complete`. Do not pass raw API responses and assume these summaries exist. A later adapter should use verified Eve summary helpers or equivalent tested normalization. Local spans appearing on disk do not prove the whole trace completed.

Span components accept Eve-shaped `spanId`, `parentSpanId`, `name`, `startTimeNs`, `endTimeNs`, `attributes`, `statusCode`, `statusMessage`; nanosecond subtraction uses bigint before converting relative durations to milliseconds. Do not convert epoch nanoseconds to Number first.

Messages are `{id,role,content,executionAction?}` presentation data, not raw Eve events. Future integration must normalize events, handle replay/deduplication, and verify execution mappings. Traces can contain multiple sessions; session filtering must not silently strip the trace's other spans.

`test/fixtures.js` and `test/WorkbenchFixture.jsx` are demonstrative fixtures only. No business logic or network clients are hidden in generic components.

For reload markers, the host polls `/api/v1/agents/:agentId/reloads` and supplies its `reloads` array alongside trace summaries. Fetching, authentication, observation availability, and any time-range filtering belong to the host, outside `TraceTable`. Marker timestamps are observation times; rows do not claim code-version membership. **Workbench / TraceTable / Reload Timeline** demonstrates chronological sorting and the existing two surface backgrounds. **Workbench / WorkbenchLayout / Composed Explorer** has an explicitly labeled **Simulate reload (fixture)** control. These stories remain fixture-based; the connected browser host owns live API access separately from reusable components.

## Migration to Base UI

The custom Tabs and Disclosure state/context/keyboard implementations have been removed. Button and TextField use Base UI Button and Field/Input. Select now uses Base UI selection, focus, positioning, and dismissal instead of a native select wrapper. Product consumers keep their data/callback APIs.

Our `Tabs.Trigger` maps to Base UI `Tabs.Tab`; `Disclosure` maps to `Collapsible`. Tab/disclosure panels default to `keepMounted` for local child-state preservation. Root callbacks pass through Base UI event details. For primitive-specific props, consult the corresponding Base UI API rather than adding new behavior engines.

Notice, time/duration formatting, payload rendering and layout wrappers remain ordinary semantic React compositions because there is no equivalent Base UI primitive to replace. `InspectorPanel` remains a nonmodal inline product layout (not a modal Dialog). `SpanWaterfall` remains an Even-specific inspection widget; Base UI does not provide a trace tree/waterfall. Its custom context and navigation are intentionally confined to that product feature.

No shadcn source, theme, or CSS framework was added. Shared decorative motion uses the documented duration/easing decisions and honors keyboard input and reduced-motion preferences. Base UI’s intrinsic positioning/focus/visibility styles are behavioral. See [color tokens](./src/tokens/README.md) and **Foundations / Colors** in Storybook for the custom OKLCH light/dark grid, semantic aliases, wide-gamut overrides, and contrast pairings. Shared component styles consume decision tokens; the host opts into a theme with `data-even-theme`. See [JSON options and decisions](./tokens/README.md) for the shared dimension scale, spacing/sizing decisions, and Style Dictionary pipeline. **Foundations / Dimensions** previews them. The accepted V2 palette (bundle 1.1.0) is active across components, with paired fill labels and persistent filled-action boundaries; the temporary revision comparison has been removed. Run `npm run tokens:generate` after JSON changes; `npm test` checks both generated CSS and manifest freshness.

Style Dictionary currently carries a low-severity transitive `deepmerge` advisory in its build tooling. There is no nonbreaking upstream fix available at this writing; the suggested forced downgrade removes current DTCG support. Only repository-owned token JSON is compiled. Revisit the dependency when a compatible fix is published; do not downgrade the pipeline blindly.

The supplementary gray-alpha scale is documented in **Foundations / Colors** with split-background swatches. Use it through semantic decisions only for shadows or overlays that need background blending; opaque neutrals remain the component default. See [the token guide](tokens/README.md#gray-alpha-derivation-and-usage) for derivation and regeneration.

### DOM registration and restoration

`TraceTable.scrollRef` receives its horizontal scrolling region, and `onScroll` reports scroll events on that region. Both object and callback refs follow React's attachment/cleanup contract. `selectedOperationRef` continues to register only the selected Operation action. TraceExplorer owns saved positions: its outer callback ref restores vertical scroll, and `scrollRef` restores horizontal scroll when the table actually mounts, including after loading.

`PayloadViewer.contentRef` receives the actual scrollable `<pre>` when nonempty captured content exists; absent/empty content has no code element. `TraceRawPanel.contentRef` forwards this contract and replaces the code node when `span.spanId` changes. TraceViewer uses it to restore both axes by scope and selected span, including after loading/error states. Path restoration is scope-aware and does not reset scroll when selecting another row in the same scope.

InspectorPanel restores focus through callback-ref cleanup when it still owns focus; ordinary rerenders preserve focus elsewhere. Workbench hosts register committed tab nodes to fulfill action-requested focus. Base UI still owns keyboard selection/navigation. A private viewport controller owns sticky geometry, overflow observation and scroll-idle cleanup for the lifetime of the scroller. React event props deliver scroll, wheel, touch and focus events; changing hover or tab count does not recreate this observer owner. Indicator-position subscriptions and motion snapshot observation remain separate responsibilities. See the [effect fixes](../docs/design-system/effect-fixes.md) for before/after examples and the remaining nine effects.
