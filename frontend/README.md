# Even frontend

Base UI-backed controls and React product components for the v1 trace explorer, inspector, and secondary playground. Shared defaults use decision tokens and support light/dark themes. Components have no model calls or API integration. Each component has a colocated implementation, Storybook stories, and behavior tests.

## Staging home page

The standalone app opens directly onto the workspace trace explorer. Run `npm run dev:ui` from the repository root, then open http://127.0.0.1:5173. `npm run build:ui` produces `frontend/dist`. This is an explicitly labeled staging UI with simulated data; it does not contact Eve, create sessions, or execute agents.

The table starts across all agents. Agent buttons scope the workspace source; search tags and captured-content search narrow the view. Use `has:error` to find traces with recorded errors. Column headers sort the supplied view models, keeping missing timings last. Existing resizable columns, complete-character overflow, zebra rows, and mixed data/UI typography are reused. Selecting an operation opens the existing inspector alongside or below the results, with spans, timing, and summary tabs. Closing restores focus to the operation. Filter changes clear selection. Result totals are announced to screen readers without a visible count row above the table. The page header, search/filter controls, reset action and search notices share a `surface.secondary` band above the results. The table retains its existing zebra surfaces on the page canvas.

**Generate sample trace** adds one simulated execution with a unique trace ID. Initial data includes completed traces, recorded errors, and unknown completion/timing. An unknown outcome is not presented as active or successful. The app’s theme button switches both page and portalled controls.

`pages/HomePage/HomePage.jsx` is the page composition; its colocated stories/tests cover staging, loading, empty, error/retry, search, combined filters, sorting, selection and focus. It takes supplied `agents` and trace summary view models, with `agentId` identifying each trace’s workspace source. Trace IDs must be unique in the supplied set; captured spans are optional. `actions` is a page-header slot. The sample data and generator are kept in `previewData.js` and the staging entry, outside reusable controls. Page arrangement is scoped in `HomePage.css`, consuming existing decisions. The shared library remains in `components/`.

See **Pages / HomePage / Staging** in Storybook. The browser gate also checks generated rows, filtering, the open inspector, retry, and overflow at 390px, 768px, and 1280px in both themes. Real backend data, reload aggregation, routing, and persisted filters remain later integration work.

## Search prototype

The staging home page now uses **Workbench / TraceSearch**, a controlled composition of Base UI Autocomplete. It shows “Search traces...” as its placeholder with no visible title or persistent helper text; the `label` prop supplies its persistent accessible name. Focus strengthens the search border with neutral `border.focus` (step 9) and `size.focus.inset` (1px), combined with `size.border.control` (1px) to produce a 2px edge without changing border width or layout. Invalid focus keeps `border.invalid`; forced-colors mode uses an inset system-color outline because shadows may be suppressed. Other controls retain their outer focus rings. Clicking the input opens examples; `tool:` and `agent:` suggest values from supplied traces. Arrow keys and Enter select a suggestion, Escape dismisses it, and the clear action resets the query. Filtering previews every edit. Enter or choosing a suggestion remembers up to three recent queries for that page instance. History is not persisted.

Browser checks cover both themes, 390/768/1280px widths, pointer/keyboard selection, repeated Tab dismissal, validation and matched-span navigation. The open autocomplete audit excludes only axe’s static `aria-hidden-focus` rule: Base UI temporarily hides outside controls from the accessibility tree while keeping its typeable combobox untrapped. Separate browser assertions verify that Tab closes the popup, reveals the outside tree and focuses the next control on repeated opens. Contrast and other axe rules remain enabled; manual screen-reader review remains future validation.

The canonical syntax and matching rules are in [Using the search bar](../README.md#using-the-search-bar). **Pages / HomePage / Search Prototype** and **Output Match** demonstrate failed tools versus unrelated errors, original output versus copied model history, and navigation to the source span. Structured terms have removable filter chips; the input is their source of truth. Value suggestions replace the final field term; completion at an arbitrary caret position is not implemented.

Results show a highlighted excerpt and source. Selecting the existing full-cell operation action opens the best matching span, expands its ancestors, and shows **Why this trace matched**, with links to other matching spans and recorded field names. Missing-content fixtures keep metadata searchable and display an availability note. Data remains explicitly simulated.

`src/search/traceSearch.js` matches supplied staging view models. Query parsing and payload leaf extraction are shared with the backend in `../src/search/query.js` and `../src/search/content.js`. It does not parse Eve files or implement canonical wrapper/execution pairing. The persistent backend index uses the verified Eve adapter helpers described in [the search research](../docs/research/trace-search.md). Generic controls neither inspect traces nor fetch data. `HomePage.initialQuery` initializes the page once; remount to reset the complete page state.

npx playwright install chromium

Set `EVEN_TEST_NODE_MODULES` at the root to enable real-Eve backend tests.

## Construction

`Name/Name.jsx`, `Name/Name.stories.jsx`, and `Name/Name.test.jsx` stay together. Shared interaction controls compose `@base-ui/react`; Base UI owns primitive state, context, keyboard navigation, focus, and dismissal. Even-specific cooperating parts may use their own context. Ordinary composites pass props. Native controls retain browser keyboard behavior. All components accept presentation through content and safe DOM props where applicable, with token-based defaults that callers can override.

## Presentation and overrides

`src/components/components.css` imports the generated tokens and defines defaults in the `even-components` cascade layer. Components load this shared stylesheet. Opt the host into a theme at its HTML root so portals inherit it:

```html
<html data-even-theme="dark"></html>
```

Components select **decisions**, not palette steps or dimension options:

| Purpose                                         | Decision tokens                                                                                                             |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Input surface, label, essential boundary        | `surface.page`, `text.primary`, `border.control`                                                                            |
| Solid primary action                            | `action.background`, `action.hover`, `action.foreground`                                                                    |
| Keyboard focus                                  | `focus.ring`                                                                                                                |
| Selected items and persistent markers           | `selection.background`, `selection.foreground`, `selection.indicator`                                                       |
| Pointer interaction and invalid boundaries      | `border.interaction`, `border.invalid`                                                                                      |
| Related controls and panel padding              | `space.gap.related`, `space.inset.default`; small internal padding uses `space.inset.tight`                                 |
| Compact/default control height                  | `size.control.compact`, `size.control.default`                                                                              |
| Navigation, inspector and flexible field widths | `size.navigation.preferred`, `size.panel.preferred`, `size.field.preferred`                                                 |
| Floating surface elevation                      | `shadow.floating` → shared translucent-black cast shadow for menus, selects, popovers, tooltips and dialog panels           |
| Corners and modal dimming                       | `size.radius.control`, `size.radius.panel`, `overlay.backdrop`                                                              |
| Trace table technical data, payloads and code   | `font.data` → Geist Mono, with monospace fallbacks                                                                          |
| Agent and Operation names and headers           | `font.ui` → system sans-serif                                                                                               |
| Compact status labels                           | `status.<tone>.compact-surface` (step 3), `status.<tone>.text` (step 9); unknown uses `surface.active` and `text.secondary` |
| Larger notices                                  | `status.<tone>.surface` (step 1), `status.<tone>.text`, `status.<tone>.border`                                              |
| Trace zebra rows                                | `surface.page`, `surface.secondary` (continuous across trace and reload rows)                                               |

If a purpose is missing, add a useful decision in JSON and regenerate. Control borders and in-place focus measurements use `size.border.control`, `size.focus.inset`, and `size.focus.outline`; the search field consumes these shared decisions. Other fixed details, responsive breakpoints, and provisional system-font UI typography remain ordinary CSS. Table typography uses the `font.data` decision; a broader typography scale has not been designed yet. No new component-token layer is introduced.

```jsx
<Button
  variant="primary"
  size="compact"
  className="launch-action"
  style={{ minInlineSize: "10rem" }}
>
  Run agent
</Button>
```

Ordinary, unlayered consumer CSS overrides library defaults; inline styles work too. Base UI parts also preserve `className={(state) => ...}`, `render`, refs, and event-details APIs. `TextField.className`/`style` target the input; `Select.className`/`style` target its trigger; overlay `Content` targets the popup. Use semantic tokens in overrides. For a nested theme, portal content still inherits its physical DOM host; apply the theme to the popup explicitly if it differs from the HTML theme.

The responsive workbench puts the inspector below the results when space is limited, stacks navigation on small screens, and contains table overflow in named keyboard-focusable regions. Base UI remains responsible for modal focus and overlay dismissal. Motion has not been added.

Floating menus, selects, popovers, tooltips and dialog panels share `shadow.floating` through `.even-popup`. This soft translucent-black shadow is the same in both themes; borders provide the persistent edge. Gray-alpha white overlays in dark mode remain separate from black cast shadows. Review **Primitives / Popover / Initially Open** and the nested overlay story.

Overlay portals create nested stacking contexts. A child portal sits above its parent's popup/backdrop, regardless of whether the child is a dialog, popover, menu, select, or tooltip. Keep popup/backdrop levels local to their portal rather than assigning global priority by component type. **Primitives / Dialog / Nested Overlays** demonstrates both nesting directions.

## Trace column sizing

`TraceToolbar.searchControl` replaces its default search input and clear button with a supplied control; existing callers keep their original behavior. `TraceTable.renderOperationDetail(trace)` adds noninteractive content to the full-cell operation action. That visible content participates in the action’s accessible name; callers should query the operation by a name containing its title when details are supplied. Data interpretation and selection of the matching span belong to the page.

`TraceTable` uses the self-hosted Geist Mono variable font through `decision.font.data`, with Agent and Operation columns using the regular system sans-serif through `decision.font.ui`. Those exceptions include their headers and the Operation cell button. Font assets ship with the frontend via `@fontsource-variable/geist-mono`; no runtime font CDN is needed. Other UI controls keep their existing appearance through the same UI-font decision.

Pass `aria-label` to give the results scroll region a distinct accessible name when composing multiple tables; the default is “Recorded trace results.”

`TraceTable` keeps column widths locally by default. Pass `defaultColumnWidths` for initial overrides, or `columnWidths` with `onColumnWidthsChange` for controlled widths. Keys are `startedAt`, `durationMs`, `agent`, `operation`, and `calls`; override values are finite CSS-pixel numbers, clamped to each column’s limits. Passing an empty controlled map restores defaults. Outcome has no handle and fills the remaining space with a minimum width.

Preferred/minimum widths live in the component’s `columns.js`; defaults use rem and track root text sizing. User adjustments are runtime state, rather than design tokens. Existing control-size, border, inset, and focus decisions style the handles. A native `colgroup` and fixed table layout size every row together; excess width stays in the scroll container. Cell text stays on one line and uses a fixed right-edge ellipsis when it overflows, including inside the full-cell Operation button. An internal `CellOverflow` masks complete graphemes at measured text boundaries and reserves room for a decorative marker anchored to the right inset; full text remains in the DOM and accessible names.

The resize dividers are hidden at rest and appear in Neutral 3 (`border.default`) when the header row is hovered. Hovering a handle or dragging emphasizes that handle with `border.interaction`; keyboard focus reveals its line and focus ring even without hover. Hit targets and keyboard navigation remain available while the decorative lines are hidden.

Drag a header’s right divider, or focus it and use Left/Right (8px), Shift+Left/Right (32px), Home (minimum), and End (maximum). Escape cancels an active drag. Resizing does not sort or select traces. **Controlled Column Widths** and **Narrow With Long Content** stories demonstrate state ownership, resets, and ellipsis.

**Character Ellipsis** demonstrates the standard overflow treatment with long labels and emoji. Drag Operation’s divider or use its keyboard controls; widen it to restore the full text. This is component presentation with no motion or new design tokens. The full semantic content stays mounted; ResizeObserver and font loading update the mask. Native ellipsis is a fallback where measurement is unavailable or for right-to-left content.

**Inline Ellipsis Experiment** previews native inline ellipsis on the existing resizable table. The marker follows the visible text; the remaining gap is after the marker. Its toggle compares with current fixed-marker behavior. The scoped Storybook stylesheet overrides presentation only; component defaults and typography are unchanged.

## Data boundary

The current backend returns full traces with spans and nanosecond strings. `TraceTable` and `TraceSummary` intentionally consume a **summary view model**: `traceId`, optional `label`, `startedAt`, `durationMs`, `agentNames`, `spanCount`, `modelCalls`, `toolCalls`, `errorSpanCount`, and explicit `complete`. Do not pass raw API responses and assume these summaries exist. A later adapter should use verified Eve summary helpers or equivalent tested normalization. Local spans appearing on disk do not prove the whole trace completed.

Span components accept Eve-shaped `spanId`, `parentSpanId`, `name`, `startTimeNs`, `endTimeNs`, `attributes`, `statusCode`, `statusMessage`; nanosecond subtraction uses bigint before converting relative durations to milliseconds. Do not convert epoch nanoseconds to Number first.

Messages are `{id,role,content,executionAction?}` presentation data, not raw Eve events. Future integration must normalize events, handle replay/deduplication, and verify execution mappings. Traces can contain multiple sessions; session filtering must not silently strip the trace's other spans.

`test/fixtures.js` and `test/WorkbenchFixture.jsx` are demonstrative fixtures only. No business logic or network clients are hidden in generic components.

For reload markers, the host polls `/api/v1/agents/:agentId/reloads` and supplies its `reloads` array alongside trace summaries. Fetching, authentication, observation availability, and any time-range filtering belong to the host, outside `TraceTable`. Marker timestamps are observation times; rows do not claim code-version membership. **Workbench / TraceTable / Reload Timeline** demonstrates chronological sorting and the existing two surface backgrounds. **Workbench / WorkbenchLayout / Composed Explorer** has an explicitly labeled **Simulate reload (fixture)** control. These stories remain fixture-based; this library does not yet ship a browser host connected to the backend.

## Dependency notes

The isolated frontend package keeps Storybook/React tooling out of the backend's runtime dependencies and npm tarball. Lockfile overrides select patched `glob` and `minimatch` releases for Storybook's transitive documentation tooling; revisit when upstream updates its dependency ranges.

## Migration to Base UI

The custom Tabs and Disclosure state/context/keyboard implementations have been removed. Button and TextField use Base UI Button and Field/Input. Select now uses Base UI selection, focus, positioning, and dismissal instead of a native select wrapper. Product consumers keep their data/callback APIs.

Our `Tabs.Trigger` maps to Base UI `Tabs.Tab`; `Disclosure` maps to `Collapsible`. Tab/disclosure panels default to `keepMounted` for local child-state preservation. Root callbacks pass through Base UI event details. For primitive-specific props, consult the corresponding Base UI API rather than adding new behavior engines.

Notice, time/duration formatting, payload rendering and layout wrappers remain ordinary semantic React compositions because there is no equivalent Base UI primitive to replace. `InspectorPanel` remains a nonmodal inline product layout (not a modal Dialog). `SpanWaterfall` remains an Even-specific inspection widget; Base UI does not provide a trace tree/waterfall. Its custom context and navigation are intentionally confined to that product feature.

No shadcn source, theme, CSS framework, or decorative motion was added. Base UI’s intrinsic positioning/focus/visibility styles are behavioral. When building the actual app host, follow Base UI’s portal/root-isolation setup guidance: https://base-ui.com/react/overview/quick-start.
